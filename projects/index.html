    项目实践

    把业务问题拆开，再把系统搭起来。这里记录我做过的项目，以及那些需要在性能、复杂度和维护成本之间作出的选择。

    碳普惠平台：从业务请求到链上资产

    生产实践 · Go / ChainMaker / MySQL / Redis

    我参与建设的碳普惠平台连接业务应用与区块链网络，将绿色出行记录转化为可核算、可流转的碳积分，支撑低碳行为激励与权益兑换。

    项目从存证逐步走向资产管理，难点也从“如何上链”变成了“如何在业务增长后持续稳定地运行”。我主要负责核心网关、碳积分合约与数据治理，并主导了业务与链交互的分层改造。

    遇到的问题 我的工作
    碳积分需要追溯到来源 设计类 UTXO 资产模型，开发减排方法学核算合约，支持积分产生、流转与来源追溯。
    出行记录增长至 1.2 亿级 实施分表、表结构优化及服务性能治理，支持核算与业务查询。
    活动期业务接口峰值达到 1.6 万 QPS 利用 Buffered Channel 解耦处理节奏，配合持久化与事务补录，缓解链上确认延迟对业务响应的影响。
    网关与链 SDK 耦合，升级相互影响 将链通信能力抽离为独立服务，通过接口明确业务与基础设施的边界。
    多源数据需要并行核算 使用 errgroup 编排任务，以 context 管理取消与资源回收。

    这里的 QPS 指业务接口请求峰值；链上交易通过异步流程处理。

    这段实践让我更重视方案的代价：类 UTXO 提升了追溯能力，也带来碎片和存储压力；分表改善了用户查询，却增加了跨表统计的成本；服务拆分让边界更清楚，也需要相应的维护投入。

    tinycache：把运行时知识用到缓存设计里

    开源项目 · Go / 泛型 / 内存管理 / 并发

    梳理 Go 的 map 和 GC 后，我尝试实现了一个泛型、线程安全的本地缓存库 tinycache。起点是一个具体问题：当缓存规模变大时，如何减少指针扫描与锁竞争带来的开销？

    设计参考了 BigCache 的无指针索引思路，并围绕已知类型的结构体缓存探索泛型数组存储、分片锁与 FreeList 回收。文章记录了数据结构、读写流程与设计取舍，关注这些设计各自适合什么场景、又引入了哪些限制。

    联盟链平台与协作

    BaaS：从零搭建链网络管理平台

    平台研发 · gin / go-micro / 联盟链

    我基于 gin 与 go-micro 从零搭建过 BaaS 平台基础框架，为企业提供区块链网络及应用的创建、管理与维护能力。

    工作覆盖链网络管理、国密改造、多云部署、公共代码模块与配置中心，也包括产品设计、部署维护、代码重构和 Code Review。这段经历让我开始从一个功能的实现，进一步考虑平台边界、公共能力和团队交付。

    数字身份与跨链业务

    共建与协作 · DID / CMDID-1 / 业务互通

    我参与过联盟链生态中的 DID 项目共建与开源，实践过基于合约标准的去中心化身份管理。

    也参与过不同链网络间的业务对接，支持积分兑换与使用。

    从工程问题延伸出的研究

    围绕碳普惠系统中的具体问题，我做过共识节点遴选、UTXO 碎片治理与隐私验证相关的方案设计和代码实践。

    共识提案节点遴选

    针对节点选择与异常节点识别，结合历史共识得分、离群检测、节点性能预测与图优化设计遴选机制，并衔接多轮投票、贡献计分与区块头记录。

    UTXO 碎片治理

    针对碎片累积与并发合并冲突，按来源及有效期分桶，结合软锁预留、链上负载调度、冲突重试和原子状态更新，兼顾积分消费与来源追溯。

    多源低碳行为隐私验证

    将密码学承诺、Merkle 归属验证，以及时空一致性、结果计算和唯一性约束纳入统一零知识证明电路，探索不披露原始行为明细的联合验证与结果登记。
